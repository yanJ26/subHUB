# Qwen 评估后的加固记录

本轮以 Qwen 评估报告为参考，但逐项用源码和隔离复现判断优先级。保留 Web + Gateway + SQLite 架构和统一领域模型，不接入 OpenClaw 或其他自动信息来源，也不修改 apiHUB、agentHUB、buddyHUB 三个旧仓库。

## 已实施

- 完整工作区运行时校验：数组、ID、枚举、数字、真实日历日期、外键、额度归属及来源映射。
- 所有写入必须提供修订号；业务变更、revision 和 audit 在同一事务内提交。
- 日常保存不能用空对象清空数据；审计摘要由服务端生成，敏感键覆盖 Token、Cookie、Private Key 和 Credential。
- 迁移先与现有 subHUB 合并，来源映射幂等；预览绑定输入摘要和目标 revision；每个费用冲突单独选择保留两条、保留现有或采用导入项。
- 无商业证据的 Agent（包括 WorkBuddy）只生成目录与工作记录，不制造免费权益；Agent 活跃度不冒充额度快照。
- 固定月成本只统计明确的周期订阅/自托管/混合费用；一次性、按量、充值和未知金额不伪装成月费；前端使用 Gateway 汇率。
- 生命周期按日历日处理，续费、权益到期和资产到期形成独立事件；额度 reset 不遮住 renewal。
- 用量速度不跨 quota policy 或计量方式合并，出现充值/重置式反向变化时不推算。
- 核心记录支持新增、编辑与可恢复归档；入口、关系、额度、评价和工作记录可以手工维护。
- 登录限速改为 SQLite 原子预留并跨重启保存；可信代理头默认关闭；Origin、Web 请求体大小和 Gateway 超时受控。
- 增加业务 JSON 预检恢复、完整 SQLite 在线备份/离线恢复、健康检查、结构化请求日志和审计查看。
- 清除未使用的 ChatGPT Auth、D1/Drizzle、Worker 和托管模板，以 SQL migration 作为唯一数据库 schema 来源。

## 仍属部署环境责任

代码不能替代 HTTPS 证书、反向代理端口策略、异机备份和真实服务器恢复演练。发布者必须按 operations.md 完成这些环境验收，不能仅凭单元测试宣称公网部署安全。
