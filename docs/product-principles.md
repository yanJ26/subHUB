# subHUB 产品基准

## 产品定位

subHUB 是单人使用的订阅与数字资产工具，不是面向团队的资产管理平台。信息架构只保留三个入口：

1. **总览**：一句话录入、成本概览、近期续费与到期。
2. **订阅**：查看和修改服务、方案、费用、续费与到期日期。
3. **资产**：查看和修改域名、设备、服务器、账号、仓库和网站。

## 五秒内回答的问题

- 我现在有哪些有效订阅，每月固定成本大约是多少？
- 哪些订阅或资产将在 30 天内续费或到期？
- 某项订阅的下次扣款和实际到期日分别是什么？
- 哪些资产异常、离线、已到期或尚待确认？

## 录入原则

- 首页自然语言录入是默认路径，允许用户随意组织内容。
- 系统负责在内部建立或复用服务、订阅和可选发票关系，不要求用户分步操作。
- 手工一步式表单只是模型未配置或需要精确修订时的后备入口。
- 下次续费与权益到期必须分别保存；未知信息允许留空，不得猜测。

## 不进入日常界面的内容

- 完整服务目录、部署拓扑和使用地图。
- 额度规则、用量快照、效率评价和重要工作记录。
- 业务导入恢复、旧项目迁移和审计查看等运维功能。

这些旧字段和服务器能力暂时保留，用于兼容既有数据库、导入协议和恢复流程；它们不构成用户完成普通订阅录入的前置步骤。

## 安全边界

- 不保存真实 API Key、Token、密码、Cookie、私钥或完整支付卡号。
- 自然语言原文不落库，只保存受控结构化结果和摘要。
- 模型 API Key 只能通过首页“模型设置”提交，并在 Gateway 中加密保存。
- 未知是合法状态；系统不制造虚假的金额、日期、关系或精度。
