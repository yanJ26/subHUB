# 汇率缓存与人民币年化估算

## 页面展示规则

- 首页“月均订阅成本”继续按 CNY、USD、EUR 分开展示，避免把估算值伪装成原始账目。
- “人民币年化估算”会先把每条订阅换算为年金额，再按当期参考汇率统一折算成人民币。
- 订阅记录始终保存原始价格和币种，不会因汇率更新而改写。

## 汇率来源

Gateway 默认读取欧洲中央银行（ECB）的每日欧元参考汇率 XML：

```text
https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml
```

ECB 数据以 EUR 为基准。系统直接使用 EUR/CNY，并通过 `CNY per EUR ÷ USD per EUR` 推导 USD/CNY。页面中的金额仅用于订阅预算估算，不应作为交易、报销或会计入账汇率。

可以通过 `APIHUB_EXCHANGE_RATE_URL` 替换数据地址；自定义来源必须返回兼容 ECB 格式的 XML。

## 每月刷新与失败降级

1. 每个 UTC 自然月，第一次通过身份验证的 `/v1/web/state` 请求会触发一次更新尝试。
2. 同一个月的后续页面刷新直接读取 SQLite 缓存，不再访问外部服务。
3. 即使本月更新失败，也不会在每次刷新时反复重试；系统会继续使用最近一次成功缓存。
4. 全新安装且无法联网时，使用代码内置的带日期参考值，并在页面标明“使用缓存汇率”或“系统内置汇率”。
5. 下个月第一次访问会再次尝试更新。

缓存保存在 SQLite 的 `exchange_rate_cache` 表中，包含数据日期、来源、最后尝试日期、错误码和更新时间。它不包含任何密钥或订阅敏感信息。

## 为什么不让大模型提供汇率

API Hub 的 BYOK 模型被定义为无工具的语义解析闸机，它不能保证联网，也不能证明回答采用了哪一天的可靠汇率。让模型生成汇率会把推测混入账目。因而两条链路保持独立：

- 大模型：把 Web 或 OpenClaw 的自然语言整理成待确认订阅草稿。
- 汇率模块：从明确的外部参考源读取、校验并缓存数字。

即使尚未配置大模型，汇率更新和人民币年化估算仍可独立工作。
