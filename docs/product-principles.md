# subHUB 产品基准

## 核心问题

subHUB 的首页和详情页必须帮助所有者快速回答：

1. 我拥有哪些数字服务、AI 使用权益和数字资产？
2. 它们能在哪些软件、Agent、API、设备或工作流中使用？
3. 哪些模型或能力由这些权益提供？
4. 哪些产品正在使用、试用、考虑、暂停或明确未使用？
5. 下一次续费、到期、额度失效或重置发生在什么时候？
6. 使用程度和产出价值大概如何？下一步应继续、观察、升级、降级还是停用？
7. 我的域名、设备和服务器分别由哪些服务管理，何时到期，承载了什么？

## 不做什么

- 不建立精密的 Token 会计系统。
- 不要求用户每 30 天准时填表。
- 不逐次保存聊天、提示词和模型输出。
- 不把用量高直接等同于效率高。
- 不把 API 与 Agent 设计成互斥顶级分类。
- 不在目录、快照、备注、导入或任何未来外部入口中保存真实凭据。

## 首页五秒测试

打开首页五秒内应看见：

- 正在使用、暂未使用、试用和待观察数量；
- 月度等价固定成本；
- 30 天内续费或到期项目；
- 额度压力、低产出或长期未复核的项目；
- 全部目录的第一屏，而不是宣传口号和装饰图。

## 数据精度

每个推算结果必须保留：

- 原始快照或人工输入；
- 观测时间与覆盖区间；
- 平台额度规则；
- 推算方法；
- 高、中、低可信度；
- “实际”或“估算”标记。

未知是合法状态。规则不明确时保存证据并暂不推算。
